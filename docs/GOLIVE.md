## 상세 기준

### 1. 모의투자 거래 누적 ≥ 30회
```
bot 시작 → main.py daily_trade_count 로그로 확인
telegram 알림에서 "진입 [종목]" 메시지 카운트
```
**충족하지 않은 경우**: 최소 3개월 런닝 필요.

### 2. 승률 ≥ 50%
```
모의 거래 중 수익거래 / 전체거래 ≥ 50%
예: 30거래 중 15거래 이상 수익
```
**확인**: `state_recovery.json` 또는 telegram 알림 히스토리.

### 3. 평균 R값 ≥ 0.5R
```
평균 R값 = Σ(pnl_r) / 거래수 ≥ 0.5
(R = 리스크 대비 수익 배율)
```
**예시**:
- 좋음: 30거래, 평균 R=0.8R (수익성 충분)
- 경계: 30거래, 평균 R=0.3R (엣지 약함)
- 나쁨: 30거래, 평균 R=-0.2R (손실 우세)

### 4. MDD ≤ 5%
```
최대 낙폭(Maximum Drawdown) = 최고점 이후 최대 손실액 / 최고점 잔액
```
**계산**:
```python
balance_history = [...]  # 일별 잔액
cummax = pd.Series(balance_history).cummax()
drawdown = (balance_history - cummax) / cummax
mdd = abs(drawdown.min())
```
**기준**: mdd ≤ 0.05 (5%)

### 5. 킬스위치 미발동 1개월
```
daily_max_loss_pct (기본 3%) 도달하지 않음 = 1개월 연속 안전
```
**확인**: main.py 로그에 "🛑 킬스위치 발동" 메시지 없음.

### 6. 자동매매 안정성
```
API 호출 에러 / confluence 계산 오류 등
→ error 로그 < 2회/월
```
**확인**: CloudWatch / Railway 로그 수동 점검.

### 7. 주문 대기 시간 < 5초
```
trader.py execute_signal() ~ order success
→ 평균 지연 < 5초
```
**확인**: telegram 알림 타임스탐프 / 실거래 주문 로그.

## 실전 전환 절차

### Step 1: 환경변수 설정 (반드시 2개 모두!)
```bash
# 1단계: 실전 활성화
export ENABLE_REAL_TRADING=1

# 2단계: 추가 확인
export REAL_TRADING_CONFIRM=YES
```

### Step 2: 검증
```bash
python main.py  # 첫 로그 확인
# → "⚠️실전" 메시지 출력되면 성공
```

### Step 3: 모니터링
```
첫 1주일: 일일 점검
  - 진입/청산 정상 여부
  - 주문 체결 시간
  - 손실 한도 (daily_max_loss_pct)
```

### Step 4: 점진적 확대
```
주 1: 리스크 1% (기본값 유지)
→ 주 2-4: 운영 안정성 확인 후 유지 또는 중단
```

## 체크 후 불안감을 느낀다면?

| 신호 | 조치 |
|------|------|
| 5거래 연손 | 즉시 ENABLE_REAL_TRADING=0 (모의로 복귀) |
| API 에러 반복 | KIS 인증 재확인 → 모의 재진입 |
| 심리적 불안 | 추가 모의 거래 1개월 후 재도전 |
| MDD > 5% 도달 | 심화 위험 → 중단 후 설정 검토 |

## 실전 전환 후 모니터링

### 일일 체크리스트
- [ ] 진입 조건 합리적인가 (과도한 매수/매도 없음)
- [ ] 손절/익절 타이밍 정상인가
- [ ] 텔레그램 알림 수신 정상인가
- [ ] 포지션 잔고 KIS와 동기화 정상인가

### 주간 리뷰
```
거래 통계:
  - 신호 수 (목표: 1-3회/주)
  - 승률 / 평균 R
  - 당주 누적 손익
  
알림 오류 (error count):
  - < 2회 → OK
  - ≥ 3회 → 원인 조사
```

### 월간 리포트
```
1개월 누적:
  - 거래 30회+: 데이터 충분 → 계속 운영
  - 거래 < 15회: 신호 부족 → 설정 조정 고려
  - 손실 > daily_max_loss 누적: 전략 재검토
```

## 위험 사항

### 1. 갭 다운 리스크
```
전일 신고가 → 다음날 시가 5% 이상 하락
SL이 시가 아래로 gap → 실손 발생
백테스트보다 손실 확대 가능
```
**완화**: `risk_pct` 낮추기 (0.01 → 0.005).

### 2. 뉴스/호가 흐름
```
급락장 (마켓 크래시) 발생 시:
  - 자동주문 중단 고려 (수동 판단)
  - 포지션 기계식 청산 위험
```
**완화**: 시장 환경 악화 시 ENABLE_REAL_TRADING=0.

### 3. API 지연/장애
```
KIS 네트워크 지연 → 주문 실패
또는 체결 지연 → 예상 가격과 이탈
```
**완화**: 주문 재시도 로직 (현재 구현됨).
